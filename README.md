# СИСТЕМА КОГАНЭ // 死滅回游 管理システム

Веб-интерфейс Смертельной миграции из «Магической битвы» (Jujutsu Kaisen).
Чистые HTML / CSS / JavaScript, ES-модули, без сборщика, без Bootstrap, без шаблонов.

Визуальный стиль снят с кадров аниме: люминофорно-зелёная панель CRT-монитора
с тёмно-зелёными «чернилами», строки развёртки, апертурная решётка, мерцание
питания, хроматическая аберрация, пиксельные японские надписи.

## Запуск

Проект состоит из двух частей: интерфейс (HTML/CSS/JS) и сервер на FastAPI
с базой PostgreSQL. Сервер отдаёт и то, и другое.

```bash
pip install -r requirements.txt
python -m uvicorn server.main:app --port 5173
```

Затем открыть `http://localhost:5173`.

Без переменной `DATABASE_URL` сервер поднимает локальный файл SQLite
(`kogane.db`) — удобно разрабатывать без установки PostgreSQL. На Railway
переменная есть, и используется настоящая база.

## Публикация на Railway

1. Создайте проект и добавьте **PostgreSQL** — Railway сам заведёт
   переменную `DATABASE_URL`, ничего вписывать не нужно.
2. Подключите репозиторий. Настройки сборки уже лежат в
   [railway.json](railway.json) и [Procfile](Procfile):

```
uvicorn server.main:app --host 0.0.0.0 --port $PORT
```

3. Проверка живости: `/api/health` — отвечает `{"ok": true, "database": "postgresql"}`.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | адрес PostgreSQL | Railway подставляет сам |
| `PORT` | порт | Railway подставляет сам |
| `ADMIN_EMAIL` | почта распорядителя | `admin@kogane.jp` |
| `ADMIN_PASSWORD` | пароль распорядителя | `kogane` |
| `ADMIN_CODE` | секретный код панели | `KOGANE-19` |

Три последние читаются **только при первом создании базы**. Задайте их
в Railway до первого запуска — тогда доступ сразу будет вашим. Если база уже
создана, пароль и код меняются в панели: **База системы → Безопасность**.

Схема таблиц создаётся автоматически при старте, начальные данные (свод правил,
магазин, учётная запись распорядителя) добавляются один раз.

## Доступ

Сайт закрыт: пока участник не зарегистрирован и не одобрен, реестр, таблица
очков и свод правил не показываются — на экране входа только афиша и форма.

**Три канала входа** (вкладки на экране входа):

| Канал | Что нужно |
|---|---|
| Вход | почта и пароль — для тех, у кого аккаунт уже есть |
| Регистрация | шаг 1 почта → шаг 2 создать пароль → шаг 3 анкета |
| Администрация | почта, пароль **и секретный код системы** |

### Регистрация в три шага

1. **Электронная почта** — проверяется формат и что адрес не занят
2. **Создать пароль** — не короче шести символов, с повтором
3. **Анкета персонажа** — имя, уровень, проклятая техника, что она делает,
   ник в Roblox, ник в Discord (плюс необязательное имя кандзи для таблицы)

Заявка уходит распорядителю. Пока он не одобрил — разделы системы закрыты,
участник видит только состояние заявки. Решение приходит на экран само.
При отказе видна причина, а анкета открывается с прежними ответами —
править нужно только то, о чём написал распорядитель.

Уровни: особый, первый, предпервый, второй, третий, четвёртый.

Первый вход распорядителя: **admin@kogane.jp** / пароль **kogane** / код **KOGANE-19**

Учётная запись распорядителя не входит через канал участника — только через
«Администрацию» с кодом. Неверный код панель не открывает, а попытка пишется
в журнал системы.

Смените пароль и код сразу: панель → **База системы** → **Безопасность**.
Код хранится хешем, восстановить его нельзя — только заменить. После смены
подсказка о первом входе с экрана исчезает.

## Как это работает

Данные живут в PostgreSQL. Игра общая: участники видят друг друга в реестре,
анкеты приходят распорядителю с любого устройства, очки и правила одни для всех.

**Сервер** (`server/`) — FastAPI:

| Файл | Что делает |
|---|---|
| `db.py` | подключение по `DATABASE_URL`, SQLite как запасной вариант |
| `models.py` | таблицы: users, npcs, shop_rules, base_rules, rule_history, notifications, logs, settings, sessions |
| `security.py` | пароли и код — PBKDF2-HMAC-SHA256 с индивидуальной солью |
| `seed.py` | первичное наполнение |
| `api.py` | вход, регистрация, состояние, анкета, покупка правил |
| `admin_api.py` | операции распорядителя |
| `main.py` | сборка приложения и отдача интерфейса |

**Клиент** — [js/core/store.js](js/core/store.js): держит снимок состояния,
полученный запросом `/api/state`. Чтение из снимка синхронное, поэтому разделы
интерфейса не переписывались. Любое изменение уходит на сервер, после чего
снимок обновляется. Опрос каждые 4 секунды и при возврате на вкладку — так
решение распорядителя доходит до участника само.

Всё, что меняет игру, делает сервер: он же шлёт уведомления и пишет журнал.
Клиент не может начислить себе очки — он только отправляет намерение.

Пароли не хранятся в открытом виде и не покидают сервер. Сессия — токен
в браузере; данные игры в браузере не хранятся.

## Звук

Звук включён по умолчанию, громкость — **0.55**. Браузеры не дают запускать
звук до первого действия пользователя, поэтому контекст разблокируется на
первом клике или нажатии клавиши: дальше идёт фоновый гул кинескопа (две
близкие частоты дают биение) и звуки интерфейса.

Ползунок громкости стоит в шапке **на всех экранах** — и на входе, и у
участника, и у распорядителя. Значение сохраняется между заходами
(`kogane:volume`). Клик по значку слева мгновенно выключает звук и возвращает
прежнюю громкость.

Все звуки синтезируются через WebAudio, файлов нет. Любой сбой аудио гасится
внутри `js/core/audio.js` и наружу не выходит.

## Горячие клавиши

В игровой системе клавиши **1…8** переключают разделы по порядку меню.
Не срабатывают при вводе текста и при открытом окне.

## Атрибут hidden и перекрывающие экраны

В `css/base/reset.css` есть правило:

```css
[hidden] { display: none !important; }
```

Оно обязательно. Правило браузера `[hidden] { display: none }` лежит в его
собственной таблице стилей, а **любое авторское правило перебивает её** —
`.connect { display: grid }` оставлял экран подключения на виду, хотя в
разметке стоял `hidden`. Полноэкранный оверлей висел поверх формы входа с
момента загрузки: сайт выглядел «зависшим» на `接続中`, а форма была
недоступна для нажатий.

Правило чинит сразу все такие места: экран подключения, скрытые формы входа,
шаги регистрации, разделы системы, счётчики уведомлений. **Не удаляйте его.**

Проверка на месте: страница `diag.html` создаёт элемент с классом `.connect` и
атрибутом `hidden`, затем сверяет, что он действительно скрыт.

## Если экран «завис»

Загрузка системы и подключение к барьеру пропускаются: **любая клавиша**,
клик по экрану или кнопка **«Продолжить →»**.

Выходы устроены в два слоя, чтобы экран не мог запереть ни при каких условиях:

1. Модуль `js/modules/connect.js` навешивает обработчики **до** запуска
   анимации и звука, переходит в `finally` даже при ошибке, плюс держит
   страховочный таймер на 7 секунд.
2. В `index.html` есть обычный (не модульный) скрипт: он ведёт на
   `pages/system.html` по кнопке и через 10 секунд, а также снимает
   загрузочный экран. Работает, даже если модули вообще не загрузились или
   браузер отдал их из старого кеша. Проверка доступа в `system.html` сама
   отправит участника на нужный экран.

Звук изолирован: любой сбой WebAudio (политика автозапуска, отсутствие
устройства вывода) гасится внутри `js/core/audio.js` и не попадает в поток.

## Версии файлов и кеш браузера

Сборщика нет, поэтому от старого кеша защищает метка версии `?v=N`. Она стоит
**везде**, а не только на точках входа:

- `index.html` и страницы в `pages/` — на `main.css` и на своём модуле
- `css/main.css` — на каждом `@import`
- каждый файл в `js/` — на каждом `import ... from '...'`

Так сделано намеренно. Раньше версия стояла только на точках входа, и браузер
отдавал свежий `auth.js`, но **старый `connect.js` из кеша** — новая разметка
встречалась со старым кодом, кнопка «Продолжить» оставалась без обработчика, и
экран подключения замирал. Вложенные импорты браузер кеширует по собственному
адресу, версия точки входа на них не распространяется.

**При каждом изменении кода поднимайте номер одной командой** (из корня проекта,
Git Bash; здесь с 9 на 10):

```bash
sed -i 's/?v=9/?v=10/g' index.html 404.html diag.html pages/*.html css/main.css $(find js -name "*.js")
```

Сервер дополнительно просит браузер перепроверять файлы (`Cache-Control:
no-cache` — заголовок ставится в `server/main.py` для всего, кроме `/api/`).
Ответ `304` почти ничего не стоит, а класс ошибок «старый модуль с новой
разметкой» исчезает совсем.

Если интерфейс всё же ведёт себя странно — **Ctrl+F5** (или Ctrl+Shift+R).

## Путь игрока

1. **Вход** (`index.html`) — загрузка BIOS системы, затем вход или регистрация:
   почта, пароль, подтверждение почты.
2. **Подключение** — полноэкранная анимация: «Подключение к глобальному
   барьеру...» → «Проверка личности...» → «Идентификация завершена.» →
   «Добро пожаловать в Смертельную миграцию.»
3. **Анкета** (`pages/application.html`) — имя персонажа, уровень, проклятая
   техника и что она делает, ники в Roblox и Discord. Черновик сохраняется
   автоматически. Состав полей задаётся в `APPLICATION_SCHEMA`
   (`js/data/seed.js`) — поля добавляются и убираются там одной строкой;
   ответы сервер хранит целиком, менять схему базы для этого не нужно.
4. **Рассмотрение** (`pages/pending.html`) — решение распорядителя приходит на
   экран само.
5. **Система** (`pages/system.html`) — доступ к разделам после одобрения.

## Разделы системы

| Раздел | Что внутри |
|---|---|
| Главная `基本情報` | Состояние миграции, срок объявления, барьер, свод базовых правил |
| Профиль участника `個人情報` | Имя, уровень, очки, число правил, колония, статус, анкета |
| Таблица участников `泳者一覧` | Пустая на старте, наполняется одобренными участниками. Пиксельная иконка, имя, очки, правил, колония; сортировка, фильтры, карточка по клику |
| Поиск участников `検索` | Большая строка ввода, анимация 「検索中」 с пиксельным черепом, подсветка совпадений, поиск по русскому/японскому/латинице |
| Магазин правил `規則購入` | Только заранее созданные правила, 100 очков. Свои формулировки недоступны |
| История правил `規則履歴` | Журнал добавлений и изменений + базовый свод |
| История уведомлений `通知` | Все события с фильтром по типу |
| Система администрации `管理` | Игроку — 「権限無し」 отказ доступа с записью в журнал |

Все эти разделы открываются только после одобрения анкеты. До решения
распорядителя участник видит лишь экран состояния заявки.

## Панель распорядителя (`pages/admin.html`)

- **Сводка** — состояние миграции, очередь анкет, лидеры по очкам, последние действия
- **Анкеты** — очередь заявок на регистрацию: имя, уровень, техника, ники Roblox и Discord; одобрение (с выбором уровня, колонии, стартовых очков) или отклонение с причиной
- **Участники** — очки (+1/+5/+100/−5/−100/задать), уровень, колония, статус, счётчик правил, выдача и отзыв правил, объявление выбывшим, **возврат в игру**, удаление аккаунта.
  Плюс **массовые действия**: начислить или списать очки, объявить выбывшими или вернуть в игру сразу всем, только живым или отдельной колонии. Охват и количество очков сохраняются между действиями, перед каждым — подтверждение с числом затронутых
- **Правила магазина** — создание, правка, скрытие, удаление
- **Уведомления** — создание события любого из 14 типов, адресно или всем
- **Рассылка** — по всем / живым / отдельной колонии, четыре готовых шаблона
- **Миграция** — начало и завершение, распоряжение участникам, распределение по барьерам
- **Журнал действий** — вся история с фильтром и копированием
- **База системы** — безопасность (смена секретного кода и пароля), выгрузка и загрузка JSON, очистка журнала и уведомлений, удаление предзаполненного реестра, полный сброс

### Реестр участников

Таблица стартует **пустой**. Она наполняется сама: каждый одобренный участник
появляется в списке, поиске и распределении по барьерам. Никаких заранее
вписанных персонажей в игре нет.

Демонстрационные записи (персонажи аниме) лежат в `server/seed.py` как
`DEMO_ROSTER` и при создании базы не загружаются. Если нужно посмотреть, как выглядит
заполненная таблица: панель → **База системы** → **Загрузить демо-реестр**.
Убрать их оттуда же одной кнопкой.

## Завершение миграции

Распорядитель завершает миграцию → у каждого игрока (в том числе в другой
устройстве) срывается сигнал: шум, тряска, вспышки, появляется Коганэ, вырастает
большой пиксельный череп, 死亡 и «Вы погибли.» Аккаунт остаётся неактивным до
начала следующей миграции — при повторном входе показывается финальный экран.

## Анимации

CRT-развёртка и апертурная решётка поверх всего экрана, мерцание питания,
пробегающая полоса, виньетка кинескопа, аналоговый шум, включение и выключение
монитора (`power-on` / `power-off`), появление панелей «строчной развёрткой»,
печать строк списка слева направо, посимвольный вывод текста, расшифровка
значений, набег чисел, сканирующая линия поиска, разрывы строк при изменении
данных, пиксельный переход между экранами, круговое раскрытие мобильного меню,
экран смерти с зумом черепа и тряской.

Всё построено на `transform` / `opacity` / `clip-path`. Режим CRT переключается
кнопкой в шапке (`вкл → лёгкий → выкл`), а `prefers-reduced-motion`
отключает анимации полностью.

## Данные

Базовые правила, магазин правил и демонстрационные участники (Юдзи, Хигурума,
Касимо, Хакари, Кэндзяку и другие, включая массовку из кадра со списком)
описаны в `server/seed.py` — правьте там. Они попадают в базу один раз, при её
создании; дальше правила меняются прямо в панели распорядителя.

Колонии частично каноничные (Токийская №1 и №2, Сендай, Сакурадзима,
Хоккайдо), остальные добавлены для полноты десятки; список меняется
в `js/data/labels.js`.

Шрифт интерфейса — `DotGothic16` (Google Fonts, поддерживает кириллицу и
кандзи). Без интернета подхватится системный монопиксельный шрифт.
