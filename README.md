# СИСТЕМА КОГАНЭ // 死滅回游 管理システム

Веб-интерфейс Смертельной миграции из «Магической битвы» (Jujutsu Kaisen).
Чистые HTML / CSS / JavaScript, ES-модули, без сборщика, без Bootstrap, без шаблонов.

Визуальный стиль снят с кадров аниме: люминофорно-зелёная панель CRT-монитора
с тёмно-зелёными «чернилами», строки развёртки, апертурная решётка, мерцание
питания, хроматическая аберрация, пиксельные японские надписи.

## Запуск

Проект состоит из двух частей: интерфейс (HTML/CSS/JS) и сервер на FastAPI
с базой PostgreSQL. Сервер отдаёт и то, и другое.

```bash
pip install -r requirements.txt
python -m uvicorn server.main:app --port 5173
```

Затем открыть `http://localhost:5173`.

Без переменной `DATABASE_URL` сервер поднимает локальный файл SQLite
(`kogane.db`) — удобно разрабатывать без установки PostgreSQL. На Railway
переменная есть, и используется настоящая база.

## Публикация на Railway

1. Создайте проект и добавьте **PostgreSQL** — Railway сам заведёт
   переменную `DATABASE_URL`, ничего вписывать не нужно.
2. Подключите репозиторий. Настройки сборки уже лежат в
   [railway.json](railway.json) и [Procfile](Procfile):

```
uvicorn server.main:app --host 0.0.0.0 --port $PORT
```

3. Проверка живости: `/api/health` — отвечает `{"ok": true, "database": "postgresql"}`.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | адрес PostgreSQL | Railway подставляет сам |
| `PORT` | порт | Railway подставляет сам |
| `ADMIN_EMAIL` | почта распорядителя | `admin@kogane.jp` |
| `ADMIN_PASSWORD` | пароль распорядителя | `kogane` |
| `ADMIN_CODE` | секретный код панели | `KOGANE-19` |

Три последние читаются **только при первом создании базы**. Задайте их
в Railway до первого запуска — тогда доступ сразу будет вашим. Если база уже
создана, пароль и код меняются в панели: **База системы → Безопасность**.

Схема таблиц создаётся автоматически при старте, начальные данные (свод правил,
магазин, учётная запись распорядителя) добавляются один раз.

## Доступ

Сайт закрыт: пока участник не зарегистрирован и не одобрен, реестр, таблица
очков и свод правил не показываются — на экране входа только афиша и форма.

**Три канала входа** (вкладки на экране входа):

| Канал | Что нужно |
|---|---|
| Вход | почта и пароль — для тех, у кого аккаунт уже есть |
| Регистрация | шаг 1 почта → шаг 2 создать пароль → шаг 3 анкета |
| Администрация | почта, пароль **и личный секретный код** |

### Регистрация в три шага

1. **Электронная почта** — проверяется формат и что адрес не занят
2. **Создать пароль** — не короче шести символов, с повтором
3. **Анкета персонажа** — имя, уровень, проклятая техника, что она делает,
   ник в Roblox, ник в Discord и карточка мувсета из Roblox Workshop

Заявка уходит распорядителю. Пока он не одобрил — разделы системы закрыты,
участник видит только состояние заявки. Решение приходит на экран само.
При отказе видна причина, а анкета открывается с прежними ответами —
править нужно только то, о чём написал распорядитель.

Уровни: особый, первый, предпервый, второй, третий, четвёртый.

## Аккаунты игроков и обновления сайта

Обновление кода не трогает уже заведённые аккаунты и записи реестра.

- Первичное наполнение (`server/seed.py`) добавляет запись, **только если такой
  почты ещё нет**: пароли и коды, изменённые в панели, переживают перезапуск.
- Изменения схемы делаются через `ensure_columns()` в `server/db.py` —
  это `ALTER TABLE ADD COLUMN`, таблицы не пересоздаются и данные не трогаются.
- Ничего удаляющего при старте сервера не выполняется.

Участников удаляют только три явных действия распорядителя, каждое
с подтверждением: **Удалить аккаунт** в карточке участника, массовое действие
и **Сбросить систему** в «Базе системы» (там же нужно вручную ввести слово
«СБРОС»). Больше игроков не удаляет ничто.

## Если участник пропал из таблицы

Проверять по порядку, сверху вниз — первое совпадение и есть причина.

**1. Аккаунт жив, но анкета не одобрена.** Панель → **Анкеты** → вкладка
**Все аккаунты**: там каждый заведённый аккаунт с его состоянием. В таблицу
попадают только одобренные. Если участник в списке есть — примите его анкету,
и он вернётся в реестр вместе с очками.

**2. База временная.** Откройте `/api/health`. Должно быть
`"database": "postgresql"`. Если там `"sqlite"` и `"ephemeral": true` —
сайт пишет в файл внутри контейнера, а он стирается при каждом развёртывании:
именно поэтому участники исчезают «после обновления». Лечится добавлением
переменной: Railway → сервис сайта → **Variables** → **Add** → **Reference** →
`Postgres.DATABASE_URL` → перезапуск.

С этой версии сервер в таком случае **не запускается вовсе** и пишет причину
в логи: лучше заметная поломка, чем молчаливая потеря аккаунтов. Распорядителю
предупреждение видно и в панели → **База системы**.

**3. Аккаунт заводили до перехода на PostgreSQL.** До этой версии данные жили
в `localStorage` браузера, а не на сервере: такие аккаунты в общей базе никогда
не появлялись и восстановлению не подлежат — нужно зарегистрироваться заново.

**4. Кто-то нажал «Сбросить систему»** или удалил аккаунт вручную. Смотрите
панель → **Журнал действий**: там есть записи `db-reset`, `users-purge`
и `delete-user` с почтой распорядителя и временем.

## Почта занята прежней регистрацией

Система не даёт завести два аккаунта на один адрес. Если при регистрации
пишет, что адрес уже зарегистрирован, освободить его можно двумя способами.

**Один аккаунт.** Панель → **Анкеты** → вкладка **Все аккаунты** → строка
нужного адреса → **Удалить аккаунт**. Удаляются анкета, очки и купленные
правила этого участника, почта сразу свободна. Остальных не касается.

**Все сразу.** Панель → **База системы** → **Удалить все аккаунты участников**.
Подтверждение двойное: сначала окно с числом аккаунтов, затем нужно ввести
слово `УДАЛИТЬ`. Свод правил, магазин, миграция, журнал и учётные записи
распорядителей остаются на месте — в отличие от «Полного сброса», который
возвращает базу к начальному состоянию целиком.

## Как это работает

Данные живут в PostgreSQL. Игра общая: участники видят друг друга в реестре,
анкеты приходят распорядителю с любого устройства, очки и правила одни для всех.

**Сервер** (`server/`) — FastAPI:

| Файл | Что делает |
|---|---|
| `db.py` | подключение по `DATABASE_URL`, SQLite как запасной вариант |
| `models.py` | таблицы: users, npcs, shop_rules, base_rules, rule_history, notifications, logs, settings, sessions |
| `db.py` → `ensure_columns()` | досоздаёт колонки, появившиеся после первого запуска: `create_all` этого не делает, а база на Railway уже существует |
| `db.py` → `deployed()` | отличает хостинг от своей машины: на хостинге без `DATABASE_URL` сервер не стартует, чтобы не писать в файл, который сотрётся |
| `security.py` | пароли и код — PBKDF2-HMAC-SHA256 с индивидуальной солью |
| `seed.py` | первичное наполнение |
| `api.py` | вход, регистрация, состояние, анкета, покупка правил |
| `admin_api.py` | операции распорядителя |
| `main.py` | сборка приложения и отдача интерфейса |

**Клиент** — [js/core/store.js](js/core/store.js): держит снимок состояния,
полученный запросом `/api/state`. Чтение из снимка синхронное, поэтому разделы
интерфейса не переписывались. Любое изменение уходит на сервер, после чего
снимок обновляется. Опрос каждые 4 секунды и при возврате на вкладку — так
решение распорядителя доходит до участника само.

Всё, что меняет игру, делает сервер: он же шлёт уведомления и пишет журнал.
Клиент не может начислить себе очки — он только отправляет намерение.

Пароли не хранятся в открытом виде и не покидают сервер. Сессия — токен
в браузере; данные игры в браузере не хранятся.

## Доступ из любой страны

У страниц **нет ни одного обращения на чужие адреса**. Раньше шрифт грузился
с `fonts.googleapis.com`, и там, где этот адрес закрыт, браузер ждал ответа
и держал экран пустым — сайт выглядел сломанным без VPN.

Теперь шрифт лежит рядом с сайтом: `assets/fonts/dotgothic16-subset.woff2`,
35 КБ — только те знаки, что нужны интерфейсу (латиница, кириллица, обе каны
и кандзи с экранов). Отдаётся тем же сервером, что и страницы, поэтому
работает одинаково везде и с VPN, и без него.

Проверить: откройте `diag.html` → раздел **Шрифт интерфейса**, строка
«Запросы на чужие адреса» должна показывать «нет».

Единственное исключение — **музыка событий по ссылке YouTube**: она идёт
с их серверов, и там, где YouTube закрыт, ролик не запустится. Это не ломает
ни событие, ни сайт: оформление применяется как обычно, а вместо записи
включается тема системы. Если участники в основном оттуда, где YouTube
недоступен, поставьте событию источник **«Тема системы»** — панель →
**Ивенты** → карточка события.

Шрифт DotGothic16 распространяется по лицензии SIL OFL 1.1 (текст —
`assets/fonts/OFL.txt`), включать его в проект разрешено.

## Телефоны и планшеты

Правила для узких экранов собраны в [css/layout/responsive.css](css/layout/responsive.css)
и подключаются последними. Что там учтено:

- **Шапка.** На экране 375 px правая часть уезжала за край на 33 пикселя —
  регулятор громкости и кнопки обрезались, дотянуться до них было нельзя.
  Теперь блок сжимается и переносится, ползунок короче, подпись громкости
  скрыта, заголовок системы уступает место кнопкам.
- **Пальцы, а не курсор.** Кнопки от 36 px, пункты меню от 46 px, поля 44 px,
  ползунок громкости вдвое толще.
- **Поля ввода 16 px.** Ниже этого Safari на iPhone приближает страницу при
  касании поля и обратно уже не отдаляет.
- **Меню.** Выдвигается кнопкой, закрывается касанием мимо (затемнение),
  клавишей Esc и выбором раздела.
- **Переносы.** Заголовки панелей, подсказка поиска, подвал карточки правила
  и длинные кнопки в опасной зоне переносятся вместо того, чтобы вылезать.
- **Телефон лёжа.** При высоте меньше 480 px шапка ужимается, подвал убирается.
- **Касание вместо наведения.** Подсветка строк реестра и плиток включается
  только там, где есть мышь: на сенсорном экране она залипала после касания.
- **Событие «парад».** На узком экране фонарей девять вместо восемнадцати —
  слабым устройствам легче.

Проверялось замерами на 375×812 (телефон) и 768×1024 (планшет): ни один
элемент не выходит за край, ширина документа равна ширине экрана, все восемь
разделов участника и все одиннадцать панелей распорядителя открываются.

## Звук

Звук включён по умолчанию, громкость — **0.55**. Браузеры не дают запускать
звук до первого действия пользователя, поэтому контекст разблокируется на
первом клике или нажатии клавиши: дальше идёт фоновый гул кинескопа (две
близкие частоты дают биение) и звуки интерфейса.

Ползунок громкости стоит в шапке **на всех экранах** — и на входе, и у
участника, и у распорядителя. Значение сохраняется между заходами
(`kogane:volume`). Клик по значку слева мгновенно выключает звук и возвращает
прежнюю громкость.

Все звуки синтезируются через WebAudio, файлов нет — в том числе музыка
ивентов (`js/core/music.js`). Любой сбой аудио гасится внутри
`js/core/audio.js` и наружу не выходит. Снятая громкость глушит и музыку
события: она не играет «в тишине», занимая процессор.

## Горячие клавиши

В игровой системе клавиши **1…8** переключают разделы по порядку меню.
Не срабатывают при вводе текста и при открытом окне.

## Атрибут hidden и перекрывающие экраны

В `css/base/reset.css` есть правило:

```css
[hidden] { display: none !important; }
```

Оно обязательно. Правило браузера `[hidden] { display: none }` лежит в его
собственной таблице стилей, а **любое авторское правило перебивает её** —
`.connect { display: grid }` оставлял экран подключения на виду, хотя в
разметке стоял `hidden`. Полноэкранный оверлей висел поверх формы входа с
момента загрузки: сайт выглядел «зависшим» на `接続中`, а форма была
недоступна для нажатий.

Правило чинит сразу все такие места: экран подключения, скрытые формы входа,
шаги регистрации, разделы системы, счётчики уведомлений. **Не удаляйте его.**

Проверка на месте: страница `diag.html` создаёт элемент с классом `.connect` и
атрибутом `hidden`, затем сверяет, что он действительно скрыт.

## Если экран «завис»

Загрузка системы и подключение к барьеру пропускаются: **любая клавиша**,
клик по экрану или кнопка **«Продолжить →»**.

Выходы устроены в два слоя, чтобы экран не мог запереть ни при каких условиях:

1. Модуль `js/modules/connect.js` навешивает обработчики **до** запуска
   анимации и звука, переходит в `finally` даже при ошибке, плюс держит
   страховочный таймер на 7 секунд.
2. В `index.html` есть обычный (не модульный) скрипт: он ведёт на
   `pages/system.html` по кнопке и через 10 секунд, а также снимает
   загрузочный экран. Работает, даже если модули вообще не загрузились или
   браузер отдал их из старого кеша. Проверка доступа в `system.html` сама
   отправит участника на нужный экран.

Звук изолирован: любой сбой WebAudio (политика автозапуска, отсутствие
устройства вывода) гасится внутри `js/core/audio.js` и не попадает в поток.

## Версии файлов и кеш браузера

Сборщика нет, поэтому от старого кеша защищает метка версии `?v=N`. Она стоит
**везде**, а не только на точках входа:

- `index.html` и страницы в `pages/` — на `main.css` и на своём модуле
- `css/main.css` — на каждом `@import`
- каждый файл в `js/` — на каждом `import ... from '...'`

Так сделано намеренно. Раньше версия стояла только на точках входа, и браузер
отдавал свежий `auth.js`, но **старый `connect.js` из кеша** — новая разметка
встречалась со старым кодом, кнопка «Продолжить» оставалась без обработчика, и
экран подключения замирал. Вложенные импорты браузер кеширует по собственному
адресу, версия точки входа на них не распространяется.

**При каждом изменении кода поднимайте номер одной командой** (из корня проекта,
Git Bash; здесь с 11 на 12):

```bash
sed -i 's/?v=11/?v=12/g' index.html 404.html diag.html pages/*.html css/main.css $(find js -name "*.js")
```

Сервер дополнительно просит браузер перепроверять файлы (`Cache-Control:
no-cache` — заголовок ставится в `server/main.py` для всего, кроме `/api/`).
Ответ `304` почти ничего не стоит, а класс ошибок «старый модуль с новой
разметкой» исчезает совсем.

Если интерфейс всё же ведёт себя странно — **Ctrl+F5** (или Ctrl+Shift+R).

## Путь игрока

1. **Вход** (`index.html`) — загрузка BIOS системы, затем вход или регистрация:
   почта, пароль, подтверждение почты.
2. **Подключение** — полноэкранная анимация: «Подключение к глобальному
   барьеру...» → «Проверка личности...» → «Идентификация завершена.» →
   «Добро пожаловать в Смертельную миграцию.»
3. **Анкета** (`pages/application.html`) — имя персонажа, уровень, проклятая
   техника и что она делает, ники в Roblox и Discord. Черновик сохраняется
   автоматически. Состав полей задаётся в `APPLICATION_SCHEMA`
   (`js/data/seed.js`) — поля добавляются и убираются там одной строкой;
   ответы сервер хранит целиком, менять схему базы для этого не нужно.
4. **Рассмотрение** (`pages/pending.html`) — решение распорядителя приходит на
   экран само.
5. **Система** (`pages/system.html`) — доступ к разделам после одобрения.

| Раздел | Что внутри |
|---|---|
| Главная `基本情報` | Состояние миграции, срок объявления, барьер, свод базовых правил |
| Профиль участника `個人情報` | Имя, уровень, очки, число правил, колония, статус, анкета |
| Таблица участников `泳者一覧` | Пустая на старте, наполняется одобренными участниками. Пиксельная иконка, имя, очки, правил, колония; сортировка, фильтры, карточка по клику |
| Поиск участников `検索` | Большая строка ввода, анимация 「検索中」 с пиксельным черепом, подсветка совпадений, поиск по русскому/японскому/латинице |
| Магазин правил `規則購入` | Только заранее созданные правила, 100 очков. Свои формулировки недоступны |
| История правил `規則履歴` | Журнал добавлений и изменений + базовый свод |
| История уведомлений `通知` | Все события с фильтром по типу |
| Система администрации `管理` | Игроку — 「権限無し」 отказ доступа с записью в журнал |

Все эти разделы открываются только после одобрения анкеты. До решения
распорядителя участник видит лишь экран состояния заявки.

## Панель распорядителя (`pages/admin.html`)

- **Сводка** — состояние миграции, очередь анкет, лидеры по очкам, последние действия
- **Анкеты** — очередь заявок на регистрацию: имя, уровень, техника, ники Roblox и Discord; одобрение (с выбором уровня, колонии, стартовых очков) или отклонение с причиной
- **Участники** — очки (+1/+5/+100/−5/−100/задать), уровень, колония, статус, счётчик правил, выдача и отзыв правил, объявление выбывшим, **возврат в игру**, удаление аккаунта.
  Плюс **массовые действия**: начислить или списать очки, объявить выбывшими или вернуть в игру сразу всем, только живым или отдельной колонии. Охват и количество очков сохраняются между действиями, перед каждым — подтверждение с числом затронутых
- **Правила магазина** — создание, правка, скрытие, удаление
- **Уведомления** — одно событие выбранного типа: всем или одному участнику
- **Рассылка** — обращение к группе: всем / живым / отдельной колонии, четыре готовых шаблона
- **Миграция** — объявление новой (со стартовыми 85 очками и подтверждением участия),
  досрочное закрытие подтверждения, завершение, распоряжение участникам
- **Ивенты** — запуск и остановка общих событий (см. ниже)
- **Распорядители** — учётные записи панели: завести, переименовать, сменить пароль и код, удалить
- **Журнал действий** — вся история с фильтром и копированием
- **База системы** — безопасность (смена секретного кода и пароля), выгрузка и загрузка JSON, очистка журнала и уведомлений, удаление предзаполненного реестра, полный сброс

### Уведомления и рассылка — в чём разница

Оба раздела кладут запись в «Историю уведомлений» участника. Различаются тем,
**что именно** отправляется и **кому**.

| | Уведомления `通知作成` | Рассылка `一斉通知` |
|---|---|---|
| Что отправляет | одно событие выбранного типа | текстовое обращение от системы |
| Тип записи | любой из 14 (очки, штраф, правило, колония, уровень, выбывание…) | всегда «сообщение системы» |
| Кому | всем **или одному** участнику из списка | группе: всем, только тем, кто в игре, или одной колонии |
| Готовые тексты | нет | четыре шаблона |
| Проверка на себе | нет | есть — «Показать себе» |

Правило простое: **адресно и с типом события — «Уведомления», объявление
группе — «Рассылка»**. Начисления очков, выдача правил и решения по анкетам
уведомления создают сами: вручную дублировать их не нужно.

## Ход игры: три фазы

Система живёт в одном из трёх состояний, и оформление меняется вместе с ним.

| Фаза | Что это | Как выглядит |
|---|---|---|
| **Нейтральный период** `休止期間` | между миграциями | голубое небо с облаками, стеклянные панели, светлые тона |
| **Подтверждение участия** `参加確認` | миграция объявлена, идёт отсчёт | янтарная палитра, у каждого открыто окно с кнопкой |
| **Миграция идёт** `進行中` | игра в разгаре | тёмная палитра, багровые и фиолетовые отсветы |

### Нейтральный период

Начинается сразу после завершения миграции. Сайт открыт: профиль, таблицы,
статистика, история уведомлений, поиск. Закрыты игровые механики — покупка
правил отклоняется и на кнопке, и на сервере. На главной висит плашка:
«Сейчас идёт нейтральный период. Следующая миграция ещё не началась.
Ожидайте объявления распорядителя».

Следующая миграция сама не начинается: её объявляет распорядитель кнопкой
**Начать новую миграцию**.

### Подтверждение участия

Нажатие кнопки не запускает миграцию сразу. Сначала пятнадцать минут идёт
подтверждение: у каждого участника открывается окно с отсчётом и **одной**
кнопкой «Принять участие» — отказа нет.

При объявлении миграции всем начисляется стартовые **85 очков**, счёт
предыдущей миграции обнуляется, купленные правила сбрасываются.

Когда отсчёт закончился (или распорядитель закрыл окно досрочно кнопкой
в панели → **Миграция**):

- подтвердившие входят в игру, счётчик пропусков обнуляется;
- остальным засчитывается пропуск, они остаются вне барьера.

### Счётчик пропусков

У каждого участника счёт вида **0/3** — сколько миграций пропущено **подряд**.
Одно подтверждённое участие обнуляет его. Распорядитель видит счётчик в панели
рядом с каждым игроком, участник — в своём профиле. На пределе (3/3) строка
в списке распорядителя помечается красным.

## Таблицы лидеров

В разделе «Таблица участников» три вкладки:

| Вкладка | Что показывает |
|---|---|
| **Реестр** `泳者一覧` | обычная таблица с фильтрами и сортировкой — как была |
| **Лучшие в этой миграции** `今回` | счёт текущей миграции, обнуляется при запуске новой |
| **Лучшие за всё время** `総合` | общий счёт за всё существование сайта, не обнуляется никогда |

Общий счёт копится сам: каждое начисление очков прибавляется к нему.
Списания уменьшают счёт текущей миграции, но историю не переписывают.

## Карточка мувсета

В анкете вместо имени кандзи участник загружает **карточку своего персонажа
из Roblox Workshop**. Снимок уменьшается прямо в браузере (длинная сторона
до 1100 точек, JPEG с подбором качества) и хранится в базе строкой `data:` —
файловая система контейнера на Railway стирается при каждом развёртывании,
поэтому складывать картинки в файлы нельзя.

Распорядитель видит карточку в окне рассмотрения анкеты рядом с ответами,
после одобрения она остаётся в профиле участника.

## Ивенты

Общее событие для всех сразу. Запускает только распорядитель:
панель → **Ивенты**. Пока событие идёт, у каждого участника меняется
оформление системы, играет своя музыка и висит метка в шапке.

| Событие | 日本語 | Что происходит |
|---|---|---|
| Сукуна в истинной форме | 宿儺・真の姿 | Люминофор выгорает в багровый, экран рассекают следы ударов |
| Сукуна против Годзё | 宿儺 対 五条 | Экран поделён пополам: левая половина багровая (Сукуна), правая голубая (Годзё), между ними рваный шов и вспышки |
| Парад тысячи духов | 百鬼夜行 | Фиолетовый сумрак, снизу поднимаются фонари шествия |

Событие идёт, пока его не остановят. Новость о запуске приходит всем
в историю уведомлений, запуск и остановка пишутся в журнал с именем
распорядителя. Кнопка «Посмотреть у себя» показывает оформление только
на своём экране — другим ничего не уходит.

Оформление держится на переопределении палитры (`css/effects/events.css`):
интерфейс целиком собран на CSS-переменных, поэтому событие перекрашивает
сразу все панели, кнопки и таблицы. Эффекты лежат отдельным слоем поверх
экрана и не перехватывают нажатия.

### Музыка событий

У каждого события свой источник звука, он настраивается прямо в карточке
события (панель → **Ивенты**):

| Источник | Что делает |
|---|---|
| **Ссылка YouTube** | ролик играет во встроенном проигрывателе YouTube |
| **Свой звуковой файл** | ссылка на `.mp3`/`.ogg`, играет обычным `<audio>` |
| **Тема системы** | написанная тема, собирается в браузере из осцилляторов |

По умолчанию: Сукуна и столкновение — по ссылкам на YouTube, парад — тема
системы. Если ролик не открылся (нет сети, ролик удалён, страна закрыта),
включается тема системы: без музыки событие не останется.

Сами записи в проект **не копируются**. Чужой трек нельзя выложить у себя,
и скачивать его с YouTube тоже нельзя — поэтому играет встроенный
проигрыватель YouTube, то есть звук идёт с их серверов, а просмотр
засчитывается автору ролика. Файлов со звуком в репозитории нет вообще.

**Почему музыка может не начаться сама.** Браузер не разрешает звук, пока
человек ничего не нажал на странице — это его собственное правило, обойти
нельзя. Если запуск отклонён, рядом с меткой события появляется кнопка
**«♪ включить музыку»**: одно нажатие, и запись идёт. Дальше, в пределах
этой вкладки, всё включается само.

Громкость записи слушается общего ползунка в шапке: снятая громкость
останавливает музыку, возвращённая — заводит заново.

### Реестр участников

Таблица стартует **пустой**. Она наполняется сама: каждый одобренный участник
появляется в списке, поиске и распределении по барьерам. Никаких заранее
вписанных персонажей в игре нет.

Демонстрационные записи (персонажи аниме) лежат в `server/seed.py` как
`DEMO_ROSTER` и при создании базы не загружаются. Если нужно посмотреть, как выглядит
заполненная таблица: панель → **База системы** → **Загрузить демо-реестр**.
Убрать их оттуда же одной кнопкой.

## Завершение миграции и экран выбывания

Завершение миграции переводит систему в нейтральный период: участники выходят
из барьера, но сайтом продолжают пользоваться — так требует сам нейтральный
период, иначе смотреть таблицы и профиль было бы негде.

Экран выбывания остался за отдельным решением распорядителя: **«Объявить
выбывшим»** в карточке участника и массовое действие «Объявить выбывшими».
Тогда у игрока срывается сигнал: шум, тряска, вспышки, появляется Коганэ,
вырастает большой пиксельный череп, 死亡 и «Вы погибли.» Снимается это
кнопкой «Вернуть в игру» или началом новой миграции.

## Анимации

CRT-развёртка и апертурная решётка поверх всего экрана, мерцание питания,
пробегающая полоса, виньетка кинескопа, аналоговый шум, включение и выключение
монитора (`power-on` / `power-off`), появление панелей «строчной развёрткой»,
печать строк списка слева направо, посимвольный вывод текста, расшифровка
значений, набег чисел, сканирующая линия поиска, разрывы строк при изменении
данных, пиксельный переход между экранами, круговое раскрытие мобильного меню,
экран смерти с зумом черепа и тряской.

Всё построено на `transform` / `opacity` / `clip-path`. Режим CRT переключается
кнопкой в шапке (`вкл → лёгкий → выкл`), а `prefers-reduced-motion`
отключает анимации полностью.

## Данные

Базовые правила, магазин правил и демонстрационные участники (Юдзи, Хигурума,
Касимо, Хакари, Кэндзяку и другие, включая массовку из кадра со списком)
описаны в `server/seed.py` — правьте там. Они попадают в базу один раз, при её
создании; дальше правила меняются прямо в панели распорядителя.

Колонии частично каноничные (Токийская №1 и №2, Сендай, Сакурадзима,
